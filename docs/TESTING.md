# Testing and verification

## Automated checks

- `npm test`: five focused tests cover traveler/count/date validation, impossible dates, cancellation eligibility, strong/matched passwords, and safe return URLs.
- `npm run test:integration`: real HTTP and Atlas checks using uniquely named disposable users and catalog entries. Cleanup is restricted to records generated by that invocation.
- `npm run lint`, `npm run typecheck`, `npm run build`: quality and production compilation checks.
- Run seed twice to verify no duplicate destination/package/admin records and no overwritten data.

## Integration coverage
Public routes; registration; duplicate email; invalid login; cookie flags; USER/admin denial; unauthenticated denial; profile persistence; origin rejection; past date and invalid traveler counts; price tampering; request idempotency; cross-user read/pay/cancel denial; failed payment and retry; concurrent successful payments with one record; booking history/details; cancellation and atomic refund; repeat cancellation/payment rejection; admin pages; password-hash exclusion; destination/package create/edit/deactivate; historic price preservation; invalid completion transition; package availability.

## Browser checklist
Desktop/tablet/mobile layout, mobile menu, search/filter results, sorting, package details, registration/login, traveler entry/review, payment, confirmation, history, profile, admin editor/day controls, deactivation confirmation, images, console errors and horizontal overflow. Production verification repeats the HTTP/data checks against the HTTPS deployment and inspects the actual live UI.

## Results
Results and deployment evidence are recorded in `VERIFICATION.md` after final checks. A successful build alone is not treated as proof of live database connectivity or payment behavior.

## Boundaries
Demo payments verify application state transitions only. They do not verify real banking, supplier reservations, delivery of travel services or financial compliance. Integration tests need Atlas access and admin credentials; never print those values or commit the environment file.
